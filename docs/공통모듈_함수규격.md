# 공통 모듈 함수 규격 합의서 (moim/common)

이 문서는 `moim/common` 에서 **아직 비어 있는 함수**(`NotImplementedError`)와 **일부만 채워진 함수**의 이름, 받는 값, 돌려주는 값을 팀이 미리 맞추기 위한 합의서다.
모든 규칙은 [`docs/규약.md`](규약.md)와 `moim/common/rules.py` 를 따르며, 함수마다 규약 값을 실제 예로 보였다.

- 함수 이름과 인자는 스켈레톤 그대로다(규약 8). 바꾸지 않고, 필요한 함수는 **추가만** 한다.
- "담당 기능"은 스켈레톤 주석에 적힌 기능이고, **구현 담당자**는 아래 기능 담당표와 팀 공동 작업 담당표에 따라 적었다. 사람별 전체 할 일은 [역할분담_작업순서.md](역할분담_작업순서.md)에 있다.
- 규격을 바꾸려면 `moim/common` 병합 요청 설명에 무엇을 왜 바꿨는지 적는다(규약 8).

### 상태 표시: 제안과 확정

| 상태 | 뜻 | 바꾸는 방법 |
|---|---|---|
| **확정** | 구현 담당자가 확인해 이대로 구현한다. 다른 사람은 이 규격을 믿고 불러 써도 된다 | 바꾸려면 담당자와 이 함수를 쓰는 기능 담당자가 함께 정하고 합의 기록에 남긴다 |
| 제안 | 문서 작성자가 규약.md·스켈레톤 주석·기본 테스트를 보고 적은 초안이다. 아직 담당자가 확인하지 않았다 | 구현 담당자가 읽고 ① 그대로면 `제안` → `**확정** — 이름 (날짜)` ② 고칠 곳이 있으면 고친 뒤 확정하고, 바뀐 점을 합의 기록에 적는다 |

- 현재 확정: **손가인(기능 4)** 담당 부분 — 1-1 `money.split` 비율 분배, 3-8 `expense_shares`, 3-9 `member_shares`, 3-10 `is_locked`, 자료 항목 `weights`·`locks`·`transfers`·`recurring_id`.
- 나머지는 모두 **제안**이다. 각 담당자는 자기 절을 확인해 상태를 바꾼다. 내가 불러 쓰는 남의 함수가 제안 상태면, 담당자에게 확정을 부탁한 뒤 쓴다.

## 0. 모든 함수에 공통으로 적용하는 약속

> 상태: 제안 — 전원 확인 후 확정. 금액·소수점·기간·삭제 표시·미분류는 규약.md 를 그대로 옮긴 것이고, 날짜 인자·저장 형식·오류 방식이 팀이 정할 부분이다.

| 항목 | 약속 | 규약 근거 | 예 |
|---|---|---|---|
| 금액 | 원 단위 `int`. 입력은 `money.to_won()` 으로 바꾼다 | 규약 1 | `"36,000원"` → `36000`, `"1234.5"` → `1235` |
| 소수점 | 사사오입(`rules.ROUNDING = "HALF_UP"`). 파이썬 `round()` 는 쓰지 않는다 | 규약 1 | `2.5` → `3`, `3.5` → `4`, `2.4` → `2` (`round(2.5)` 는 `2`라서 틀림) |
| 날짜 인자 | `"YYYY-MM-DD"` 문자열 또는 `date` 둘 다 받는다. 안에서 `dates.parse()` 로 바꾼다 | 규약 3 | `"2026-11-12"`, `date(2026, 11, 12)` |
| 저장되는 날짜 | 자료 파일(JSON)에는 `"YYYY-MM-DD"` 문자열로 둔다(`dates.fmt()`) | 규약 3 | `"2026-02-29"` 는 없는 날짜라 `ValueError` (2028-02-29 는 됨) |
| 월 | `"YYYY-MM"` 문자열 또는 `(연, 월)` 튜플 | 규약 3 | `"2026-11"`, `(2026, 11)` |
| 기간 | `start`, `end` 모두 **포함**(`dates.in_period`) | 규약 3 | 11-10 ~ 11-20 이면 11-10, 11-20 지출 모두 들어감 |
| 삭제 표시 | `e.get("deleted")` 가 참이면 합계·정산·보고서·내보내기에서 뺀다 | 규약 6-1 | — |
| 분류 없음 | `rules.UNCATEGORIZED` (`"미분류"`) | 규약 5 | `category` 가 `None` 또는 `""` → `"미분류"` |
| 오류 | 잘못된 입력은 이유를 담은 `ValueError` 로 알린다 | — | `ValueError("0원 이하 지출은 받지 않습니다: 0")` |
| 자료 접근 | 자료는 `store.data` 에서만 읽고, 저장은 `store.save()` 만 쓴다 | 규약 7 | — |

### 지출 한 건(`e`)의 형식

`store.py` 의 `EMPTY` 주석과 기능 파일 첫머리의 추가 항목을 합친 형식이다.
상태: `weights`·`recurring_id` 는 **확정**(손가인), `deleted` 는 제안(김보근 확인), 나머지 기본 항목은 스켈레톤 그대로다.

```python
{
    "id": 7,                          # int, store.new_id()
    "date": "2026-11-12",             # str YYYY-MM-DD
    "payer": "김민수",                 # str, 명부에 있는 이름
    "amount": 36000,                  # int, 원, 1 이상
    "members": ["김민수", "이서연", "박지훈"],  # list[str], 순서가 나머지 1원 순서가 된다
    "weights": None,                  # dict[str,int] 또는 None(균등). 기능 4가 추가
    "category": "식비",                # str 또는 None(→ "미분류")
    "memo": "회의 후 저녁",             # str
    "deleted": False,                 # bool. 기능 1이 추가
    "recurring_id": None,             # 반복 지출에서 만든 경우 그 번호. 기능 4가 추가
}
```

### 명부 한 사람의 형식

```python
{"name": "김민수", "joined": "2026-09-01", "left": None}   # left: 탈퇴일 str 또는 None
```

### 다른 기능이 `EMPTY` 에 추가할 자료 항목(공통 함수가 읽는 것만)

| 항목 | 형식 | 추가하는 기능 | 읽는 공통 함수 | 상태 |
|---|---|---|---|---|
| `locks` | `[{"start": "2026-11-01", "end": "2026-11-30"}]` | 기능 4 | `queries.is_locked` | **확정** — 손가인 |
| `transfers` | `[{"date", "from", "to", "amount"}]` | 기능 4 | — | **확정** — 손가인 |
| `history` | `[{"id": 지출번호, "action": "add"/"edit"/"delete"/"restore", "before": dict 또는 None, "after": dict 또는 None, "at": "YYYY-MM-DD HH:MM:SS"}]` | 기능 1 | `ledger.insert` | 제안 — 김보근 확인 |
| `payments` | `[{"date": "2026-11-02", "member": "이서연", "amount": 20000}]` | 기능 5 | — | 제안 — 염승민 확인 |

## 1. `money.py` — 금액

### 1-1. `money.split(amount, members, payer=None, weights=None)` — 비율 분배 부분

| 항목 | 내용 |
|---|---|
| 현재 코드 | 균등 분배는 구현됨. **`weights` 가 있을 때만** 비어 있다 |
| 받는 값 | `amount: int`(0 이상), `members: list[str]`(1명 이상), `payer: str 또는 None`, `weights: dict[str, int] 또는 None` |
| 돌려주는 값 | `dict[str, int]` — `{이름: 부담액}`. 키 순서는 `members` 순서. **합계는 항상 `amount`** |
| 오류 | `members` 가 비었으면, `amount < 0` 이면, `weights` 에 참여자의 비율이 없거나 0 이하이면 `ValueError` |
| 담당 기능 | 기능 4 (공용: 기능 5의 회비 차감) |
| 구현 담당자 | 손가인 |
| 상태 | **확정** — 손가인 (2026-11-17) |

**규약 2 적용 예**

| 호출 | 계산 | 결과 |
|---|---|---|
| `split(100, ["가","나","다"], payer="나")` | 100 // 3 = 33씩, 남는 1원 → 낸 사람 나 먼저 | `{"가": 33, "나": 34, "다": 33}` (규약의 예) |
| `split(101, ["가","나","다"], payer="다", weights={"가":2,"나":1,"다":1})` | 101×2//4=50, 101×1//4=25, 25 → 합 100, 남는 1원 → 다 | `{"가": 50, "나": 25, "다": 26}` |
| `split(102, ["가","나","다"], payer="라")` | 34씩, 남는 0원 (낸 사람 라는 참여자가 아니어도 됨, 규약 6-2) | `{"가": 34, "나": 34, "다": 34}` |
| `split(101, ["가","나","다"], payer="라")` | 33씩, 남는 2원 → 라는 참여자가 아니므로 목록 순서 가, 나 | `{"가": 34, "나": 34, "다": 33}` |

**발표 예시: 10,000원을 3명이 나눌 때 (규약 2)**

| 호출 | 계산 | 결과 |
|---|---|---|
| `split(10000, ["가","나","다"], payer="나")` | 10000 // 3 = 3,333씩(합 9,999), 남는 1원 → 낸 사람 나가 참여자이므로 나 먼저 | `{"가": 3333, "나": 3334, "다": 3333}` |
| `split(10000, ["가","나","다"], payer="라")` | 3,333씩, 남는 1원 → 라는 참여자가 아니므로 목록 첫 사람 가 | `{"가": 3334, "나": 3333, "다": 3333}` |

세 사람 부담액의 합은 언제나 10,000원이다.

## 2. `dates.py` — 날짜와 기간

### 2-1. `dates.month_key(value)`

| 항목 | 내용 |
|---|---|
| 받는 값 | `value: str("YYYY-MM-DD") 또는 date` |
| 돌려주는 값 | `str` — `"YYYY-MM"` (`rules.MONTH_FORMAT`) |
| 오류 | 없는 날짜면 `ValueError` (`dates.parse` 를 그대로 쓴다) |
| 담당 기능 | 기능 6 (공용: 기능 3) |
| 구현 담당자 | 오재원 |
| 상태 | 제안 — 오재원 확인 후 확정 |

**예**: `month_key("2026-11-12")` → `"2026-11"`, `month_key(date(2028, 2, 29))` → `"2028-02"`, `month_key("2026-02-29")` → `ValueError`(2026년은 윤년이 아님)

### 2-2. `dates.months_between(start_ym, end_ym)`

| 항목 | 내용 |
|---|---|
| 받는 값 | `start_ym: (int, int)`, `end_ym: (int, int)` — `(연, 월)` 튜플 |
| 돌려주는 값 | `list[tuple[int, int]]` — 시작 달부터 끝 달까지 **둘 다 포함**, 오래된 달부터 |
| 오류 | `start_ym > end_ym` 이면 `ValueError` |
| 담당 기능 | 기능 5 (공용: 기능 3) |
| 구현 담당자 | 염승민 |
| 상태 | 제안 — 염승민 확인 후 확정 |

**규약 3 적용 예**

| 호출 | 결과 |
|---|---|
| `months_between((2026, 11), (2027, 2))` | `[(2026, 11), (2026, 12), (2027, 1), (2027, 2)]` (해 넘김은 `next_month` 사용) |
| `months_between((2026, 11), (2026, 11))` | `[(2026, 11)]` (시작·끝 포함이라 한 달) |
| `months_between((2026, 12), (2026, 11))` | `ValueError` |

> 참고: 한 달의 기간은 `month_range(2028, 2)` → `(2028-02-01, 2028-02-29)`, `month_range(2026, 2)` → `(2026-02-01, 2026-02-28)` 이다(규약 3, 윤년).

## 3. `queries.py` — 조회

### 3-1. `queries.expenses_in(store, start, end, include_deleted=False)`

| 항목 | 내용 |
|---|---|
| 받는 값 | `store: Store`, `start`, `end`: 날짜, `include_deleted: bool` |
| 돌려주는 값 | `list[dict]` — 기간 안 지출(원본 dict). **날짜순, 같은 날이면 번호순** |
| 오류 | 날짜가 잘못되면 `ValueError` |
| 담당 기능 | 기능 3 (공용: 전원) |
| 구현 담당자 | 민기슬 |
| 상태 | 제안 — 민기슬 확인 후 확정 |

**예** (11-05 3,000원, 11-10 6,000원, 11-20 9,000원(삭제 표시), 11-21 1,000원)
- `expenses_in(store, "2026-11-10", "2026-11-20")` → 11-10 한 건 (11-20 은 기간에 들지만 삭제 표시라 빠짐, 규약 3·6-1)
- `expenses_in(store, "2026-11-10", "2026-11-20", include_deleted=True)` → 11-10, 11-20 두 건

**발표 예시: 11월 30일 지출은 11월 1일~11월 30일 합계에 들어가는가 (규약 3)**

들어간다. 기간은 시작일과 끝일을 **모두 포함**한다(`dates.in_period`).

| 지출 날짜 | `expenses_in(store, "2026-11-01", "2026-11-30")` 에 | 이유 |
|---|---|---|
| 2026-10-31 | 빠짐 | 시작일 전 |
| 2026-11-01 | 들어감 | 시작일 당일 포함 |
| **2026-11-30** | **들어감** | **끝일 당일 포함** |
| 2026-12-01 | 빠짐 | 끝일 다음 날 |

예: 11-30 에 5,000원 지출이 하나 더 있으면 3-2 의 `period_total(store, "2026-11-01", "2026-11-30")` 은 `10000` 이 아니라 `15000` 이다. 한 달 기간은 `dates.month_range(2026, 11)` → `(2026-11-01, 2026-11-30)` 으로 만든다.

### 3-2. `queries.period_total(store, start, end)`

| 항목 | 내용 |
|---|---|
| 받는 값 | `store`, `start`, `end` |
| 돌려주는 값 | `int` — 기간 안 지출 금액 합(삭제 표시 제외). 지출이 없으면 `0` |
| 담당 기능 | 기능 6 (공용: 기능 3·5) |
| 구현 담당자 | 오재원 |
| 상태 | 제안 — 오재원 확인 후 확정 |

**예**: 위 자료에서 `period_total(store, "2026-11-01", "2026-11-30")` → `3000 + 6000 + 1000 = 10000`
`period_total(store, *dates.month_range(2026, 11))` 처럼 한 달 전체를 넘겨 쓴다.

### 3-3. `queries.category_of(e)`

| 항목 | 내용 |
|---|---|
| 받는 값 | `e: dict` — 지출 한 건 |
| 돌려주는 값 | `str` — 분류 이름. 없거나 빈 문자열이면 `rules.UNCATEGORIZED` |

### 3-4. `queries.category_totals(store, start, end)`

| 항목 | 내용 |
|---|---|
| 받는 값 | `store`, `start`, `end` |
| 돌려주는 값 | `dict[str, dict]` — `{분류: {"count": int, "amount": int}}`. 지출이 있는 분류만, 삭제 표시 제외 |

| 담당 | 팀 공동 "자료 파일 손상 대응" |
| 구현 담당자 | 민기슬 |
| 상태 | 제안 — 민기슬 확인 후 확정 |

### 7-3. `Store.recover()`

| 항목 | 내용 |
|---|---|
| 받는 값 | 없음 |
| 돌려주는 값 | `Store`(`self`, `load()` 와 같게) |
| 해야 할 일 | ① 깨진 자료 파일을 `data.json.broken-YYYYMMDD-HHMMSS` 로 옆에 남김 ② `backups()` 를 **최근 것부터** 읽어 `_check_shape` 를 통과하는 첫 백업을 `self.data` 로 ③ 그 경로를 `self.recovered_from` 에 ④ 쓸 백업이 없으면 `ValueError` |
| 담당 | 팀 공동 "자료 파일 손상 대응" |
| 구현 담당자 | 민기슬 |
| 상태 | 제안 — 민기슬 확인 후 확정 |

**예**: `data.json` 이 `{"members": [` 처럼 잘려 `load()` 가 실패 → `recover()` → `recovered_from == ".../backup/data-20261116-173215-000000.json"`

## 8. `log.py`·`config.py` — 로그와 설정 (팀 공동)

### 8-1. `log.get_logger(log_dir)` — 일부만 구현됨

| 항목 | 내용 |
|---|---|
| 받는 값 | `log_dir: str` — 설정 파일의 `log_dir` (예: `"logs"`) |
| 돌려주는 값 | `logging.Logger` — 이름 `"moim"` |
| 약속 | `log_dir/YYYY-MM-DD.log` 에 UTF-8 로 덧붙여 씀. 한 줄 형식 `2026-11-16 17:32:15 INFO 지출 추가 1번 36,000원`. 여러 번 불러도 핸들러를 중복으로 달지 않음 |
| 담당 | 팀 공동 "로그" |
| 구현 담당자 | 김보근 |
| 상태 | 제안 — 김보근 확인 후 확정 |

**예**: 2026-11-16 에 지출을 추가하면 `logs/2026-11-16.log` 에 `2026-11-16 17:32:15 INFO 지출 추가 1번 36,000원` 한 줄이 붙는다. 금액은 `money.fmt` 로 쉼표를 넣는다(규약 1).

### 8-2. `config.load(path="config.json")` — 항목 추가 (팀 공동: 설정 파일)

| 항목 | 내용 |
|---|---|
| 현재 코드 | 읽기는 구현됨. `DEFAULT` 에 `group`, `data` 만 있다 |
| 받는 값 | `path: str` — 설정 파일 경로 |
| 돌려주는 값 | `dict` — `DEFAULT` 위에 파일 내용을 덮은 설정. 경로 항목(`PATH_KEYS`)은 설정 파일 폴더 기준 절대 경로 |
| 해야 할 일 | `DEFAULT` 에 `config.example.json` 항목 추가: `members_file`, `rules`, `backup_dir`, `log_dir`, `treasurer`, `budget{monthly, by_category}`, `dues{monthly}`, `warn_ratio`. `PATH_KEYS` 에 `members_file`, `rules`, `backup_dir`, `log_dir` 추가 |
| 오류 | 파일이 JSON 이 아니면 `ValueError("설정 파일 형식이 잘못되었습니다: config.json")` |
| 담당 | 팀 공동 "설정 파일" |
| 구현 담당자 | 오재원 |
| 상태 | 제안 — 오재원 확인 후 확정 |

**예**: `config.example.json` 을 읽으면 `cfg["budget"]["monthly"] == 1500000`, `cfg["dues"]["monthly"] == 20000`, `cfg["treasurer"] == "김민수"` (은행 출금의 낸 사람, [은행거래내역형식.md](은행거래내역형식.md)). 금액 항목은 원 단위 정수다(규약 1).
